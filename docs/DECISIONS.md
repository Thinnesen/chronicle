# Decisions

One entry for each design change. Newest first.

- 2026-10-20: Input artifacts can come from `raw` text or an `http` URL, as in Argo, also in `spec.arguments.artifacts`. The step downloads the URL from its own Pod, so the controller and the server make no requests to user URLs. The executor saves the file as it is. Argo unpacks a tarball that it detects, but a file that changes its form by its content is a surprise; a step can unpack it. Other Argo sources (s3, gcs, git and others) need credentials per source and are not supported: use the repository of the namespace.

- 2026-10-20: The node outputs in the status have `exitCode`, the exit code of the main container, as in Argo. The controller reads it from the Pod status, so it is also there when the executor did not write a message. Placeholders: `{{tasks.x.exitCode}}`, `{{steps.x.exitCode}}`, and the node fields `id`, `startedAt` and `finishedAt`. A fan-out has no `exitCode`, because the items can have different codes.

- 2026-10-20: Global outputs as in Argo: `globalName` on output parameters and artifacts, `status.outputs`, and `{{workflow.outputs.*}}`. The engine computes the outputs from the finished nodes on each run, so a retry or a re-run gives the same result as the nodes. Reason: exit handlers and runs that report one result need them, and the Argo converter dropped them.

- 2026-10-20: `continueOn` (`failed`, `error`) on a DAG task or a step, as in Argo. A failure that continues counts as success for the depends of later tasks and does not fail the DAG or the steps; the node stays Failed. Reason: steps templates have no `depends`, so users moving from Argo had no way to go on after a failed step.

- 2026-10-20: An approval has an optional `user`. The API sets it to the caller. The validating webhook refuses a new or changed approval whose `user` is not the user of the admission request, as Kubernetes does for the username of a CertificateSigningRequest. An approval without a user stays allowed, so `kubectl patch` keeps working. Reason: the audit log and the Kubernetes events (one hour) did not keep a durable record of who approved; Argo has none either.

- 2026-10-20: The CSP allows injected styles that carry a per-page nonce (`style-src 'self' 'nonce-...'`). The server puts a new random nonce into index.html and into the header of each page; the UI gives it to `get-nonce`, which the dialog scroll lock reads. Reason: every Radix dialog injects a `<style>` for its scroll lock, and the CSP blocked it, so the lock did not work and each dialog logged a violation. `'unsafe-inline'` would allow CSS injection, and a hash does not work because the style depends on the scrollbar width.

- 2026-10-19: `synchronization` locks are Kubernetes Leases (`chronicle-lock-<name>`) with the holders in an annotation. The controller reads the Lease past its cache and writes it with the resource version of the read, so two reconciles can never both take the last slot. A finished run gives the lock back; a deleted or finished holder is dropped when another run asks. Locks are for whole runs only; the limit of a semaphore is in the spec, not in a ConfigMap as in Argo. Reason: deployment pipelines need "one at a time"; Leases need no extra store and no finalizer. Cost: the controller needs `get`, `create` and `update` on Leases in all namespaces, because RBAC cannot limit a rule to a name prefix. A compromised controller could then change other Leases, for example of leader elections; it can already create Pods in all namespaces, which is a larger power.

- 2026-10-19: `parallelism` (of the workflow, and of a `dag` or `steps` template) counts Pods only, not task nodes or suspends. A waiting Pod node is marked by its message; an admitted Pod holds its slot also before the cache shows it, so a limit is never exceeded. Reason: a fan-out of many items must not start all Pods at once; this was the most common Argo feature that chronicle lacked. Task workers limit their own work with their concurrency.

- 2026-10-19: With an archive database, the login sessions of the UI are in that database (table `sessions`, keyed by a hash of the session ID). Reason: the memory store logged every user out at each restart and allowed only one server replica. A signed cookie without server state would make logout unable to end a session. Without an archive, the memory store stays, and the chart refuses more than one server replica with a login.

- 2026-10-19: With an archive, the history limits of a CronWorkflow delete a run only after the archive has it, as the TTL does. A user who deletes a run by hand still deletes it at once: there is no finalizer, because a finalizer would block deletes while the archive is down. Lists page with a cursor (creation time and name of the last run) instead of an offset, so a deep page in a large archive costs the same as the first page. Findings of the code review (#36).

- 2026-10-19: The containers of the chronicle image in workflow Pods (the executor init container and resource steps) have a read-only root file system; the container of a user step does not. Reason: many user images write to their root file system, for example to `/tmp` or a cache. The step still runs as non-root without capabilities. There is no `podSpecPatch` (section 3.2 promised a limited one), because a patch could undo the Pod security settings. Found by the security review (#36).

- 2026-10-19: The web UI is an ops console (sidebar, Cmd+K search, tabs Graph, Timeline and Spec, a node drawer), not the signal-box panel of section 8.1. Status icons replace the signal lamps, and the graph does not draw the root node. Reason: the owner found the first UI "vibecoded" and chose the ops console direction. The design combines Argo Workflows, Argo CD, Temporal and Dagster (docs/RESEARCH.md).

- 2026-10-19: A dependency version must be at least seven days old, except for a release that fixes a known vulnerability: then the fix wins (first case: rustls 0.23.46). Dependabot enforces the seven days with a cool-down; pnpm (`minimumReleaseAge`) is a hard floor of one day for every install, also by hand. Trivy scans the image and all lockfiles in CI and every week; the Makefile pins Trivy with a SHA-256 instead of the trivy-action, whose tags were once hijacked.

- 2026-10-19: Task workers: the queue is a table in the archive database, a timeout fails the attempt (no silent redelivery), and retries come only from `retryStrategy`. Reason: one retry mechanism for Pods and tasks, and a result that arrives after a timeout can never change a finished node. Temporal also fails an activity attempt on a heartbeat timeout and retries by policy.

- 2026-10-19: The Python and Rust SDKs are hand-written builders that make plain objects, with no generated types and no runtime dependencies (the Python client uses only the standard library). The server validates on submit. A shared fixture keeps the output of the three SDKs equal. Reason: generated CRD types are large and add a generator and dependencies, but give little to a builder API. Section 6 said "the SDKs generate their workflow types from the CRD schema".

- 2026-10-19: Artifacts use one S3-compatible repository for each namespace, from a ConfigMap and a Secret with a fixed name. An artifact value is its key, and the archived log is the node field `logKey`, not an artifact. Reason: a team owns its storage and credentials; the fixed name lets the server read only these Secrets; keys reuse the parameter flow of the engine. Argo has more storage drivers and a default repository in the controller ConfigMap; chronicle supports only S3 for now.
- 2026-10-19: The e2e tests use SeaweedFS, not MinIO, as the S3 store. Reason: MinIO no longer publishes container images. Issue #25 named MinIO.

- 2026-10-18: A retry is the spec field `restart` with a generation, and retried Pods get a generation suffix in their name. Reason: the same mechanism for kubectl, GitOps, the CLI and the UI; the status stays controller-owned; and a new Pod can never be confused with a terminating Pod of the same node. Argo resets the nodes through its own API and reuses Pod names.

- 2026-10-18: The API carries Workflows as JSON objects (`google.protobuf.Struct`), not as protobuf copies of the CRD types. SDK workflow types come from the CRD schema. Reason: one definition of a workflow (the Go types and the CRD). Section 2 said "SDKs generated from the protobuf API"; now only the API clients are.
- 2026-10-18: The server impersonates the caller for every Kubernetes call, reads included, and has no unauthenticated mode. Reason: the threat model (no server-side privilege for user actions). The cost is one API client per request.

- 2026-10-18: Resource templates run in a Pod with the workflow service account, not in the controller and not with impersonation. Reason: the controller then needs no `impersonate` permission, and a step can do only what its service account can do. Manifests are parsed before substitution, so parameters cannot inject YAML.

- 2026-10-18: Suspend, stop, terminate and approvals are fields of the Workflow spec (`suspend`, `shutdown`, `approvals`). Reason: one mechanism for kubectl, GitOps, the CLI and the UI, with the same RBAC (`update` on Workflows). Argo uses spec fields for suspend and shutdown, but node changes through its own API for resume and approval.

- 2026-10-18: Workflow Pods report outputs through the termination message of the main container, written by `chronicle-exec`. Reason: Argo needs a `WorkflowTaskResult` resource and API access for each Pod. Without API access, a compromised step cannot change any Kubernetes object. The cost is a 4 KiB limit; artifacts carry larger data. Kubernetes image volumes could replace the init container later, when all supported runtimes have them.

- 2026-10-18: `when` conditions are parsed before substitution, and values are literal operands. Reason: Argo substitutes values into the expression text, so a parameter value such as `x || true` can change the condition (injection). The Argo converter keeps simple conditions as they are.

- 2026-10-18: DAG outcome follows Argo v4 (leaf tasks and their branches decide), with one change: a failure that a task tests for with its exact result (`a.Failed`, `a.Errored`) is handled. It does not fail the DAG and does not stop it with `failFast`. Reason: in Argo, an omitted leaf such as `depends: "!a.Failed && b"` fails the DAG after a handled failure, which surprises users.

- 2026-10-18: The template container is a small chronicle type without a security context, and a script source cannot have placeholders. Reason: a user who can create a Workflow must not get a privileged Pod, and parameters must never become shell code (threat model, section 6.2). Argo YAML that uses placeholders in a script source must move them to environment variables. The converter will do this.

- 2026-10-18: Microsoft Entra ID (Microsoft 365) is a first-class identity provider, with group overage through Microsoft Graph and team-level access through a Helm value `teams`. Reason: the owner wants an easy M365 login and team-level visibility for platform admins.
- 2026-10-18: Pure engine package (no I/O, no clock), applied by the controller. Reason: deterministic, table-testable and fuzzable workflow logic.
- 2026-10-18: Permissions through Kubernetes SubjectAccessReview and impersonation. Reason: one RBAC model for the UI, the CLI, `kubectl` and GitOps. Argo Workflows needs a separate SSO RBAC mapping, which users find hard.
- 2026-10-18: Connect-RPC (gRPC and HTTP/JSON from one protobuf definition). Reason: SDKs for Go, Python and Rust come from one source, and the UI can use plain HTTP/JSON.
- 2026-10-18: Own API group (`chronicle.thinnesen.com`), not the Argo group, with a converter for Argo YAML. Reason: chronicle and Argo Workflows can run in the same cluster during a migration.
- 2026-10-18: Durable task workers (activities) first, durable workflow code later. Reason: deterministic replay of user code is a large, separate problem. Step-level retry and re-run cover most needs.
